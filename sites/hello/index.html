01Get yours

  1. Pick a name and clone the repo

    The folder name is the subdomain: lowercase letters, digits and hyphens, 2–31 characters, starting with a letter. Check sites/ first — names are first come, first served.

    # with the GitHub CLI
gh repo clone DawgSecTeam/pages
cd pages
git checkout -b add-yourname

  2. Add a folder with an index.html

    One index.html with inline CSS is the simplest thing that works — no build step, no CDN dependencies. Anything the browser renders from static files is fine: HTML, CSS, JS, images, fonts.

    mkdir sites/yourname
$EDITOR sites/yourname/index.html

git add sites/yourname
git commit -m "Add yourname page"
git push -u origin add-yourname

  3. Open the pull request

    Run gh pr create --fill, or use the link GitHub prints after the push. The PR template has a short checklist; CI runs the same validator you can run locally with python3 scripts/validate.py pr.

  4. Merge means live

    A maintainer reviews — that review is the abuse gate, because pages are served on the club's domain — and merges. The deploy workflow then syncs sites/ to the server. No DNS work, no certificate work, no server access needed on your side.

Not comfortable with git? You can do it entirely in the browser: fork the repo, use Add file → Create new file, type sites/yourname/index.html as the path, paste your HTML, and open a pull request from the fork.

02What passes review

Name

  • ^[a-z][a-z0-9-]{1,30}$ — lowercase, digits, hyphens
  • 2–31 characters, starts with a letter
  • Reserved names are rejected: www, admin, api, mail, and existing club service names
  • One folder name per PR; renaming later means a new PR that deletes the old folder

Content

  • Static files only, from the extension allowlist (no executables or archives)
  • 25 MB and 2,000 files per site
  • No symlinks, no .. paths
  • It is a public web page: nothing illegal, no phishing, no malware, nothing you would not put your name on
  • Club-appropriate — it is served under dawgsec.com

03How it works

Each wildcard subdomain is rewritten to a folder: yourname.page.dawgsec.com/a/b serves sites/yourname/a/b, with the site's own index.html used for directory requests. Missing paths fall back to the club's placeholder page, so client-side-routed single-page apps should ship the entry document at the exact paths they link to. TLS is a wildcard certificate on the club's side — there is nothing certificate-related to do per site.

Deployment is all-or-nothing from the repo's point of view: the workflow validates every site, and only then syncs the tree. A failed validation never reaches the server.
